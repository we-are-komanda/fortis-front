# Fortis Demo для Windows x64

Tauri 2 открывает текущий интерфейс Fortis. В пакет входят Next.js standalone, Node.js 22 и модели из `public/`. Go backend и PostgreSQL не нужны. Существующий режим `demo` предоставляет моковые API и локальные черновики. Серверные проекты и отчёты недоступны.

При запуске оболочка поднимает собственный процесс на `127.0.0.1:43178`, ждёт готовности demo API и открывает окно. Порт постоянный для сохранения localStorage. Занятый порт вызывает ошибку, чужие процессы не завершаются. При закрытии окна процесс останавливается; при аварийном завершении оболочки Node завершится по EOF stdin.

Учебный ландшафт, Factory BIM, локальные 3D-модели и моки входят в пакет. По уточнению пользователя географические GIS-подложки загружаются из OpenFreeMap, OpenStreetMap и OpenTopoMap: для них нужен интернет. CSP разрешает только эти внешние картографические источники. Сервер Fortis не используется. Подписи и ограничения учебных данных сохранены.

При ошибке онлайн-карты или начальной загрузке дольше 15 секунд включается ближайший локальный район: два участка по 20×20 км вокруг «Завода Альфа» (37.1° E, 55.1° N) и «Тестового предприятия» (40° E, 55° N), суммарно 657 тайлов, около 11.6 МБ. Появляется сообщение, кнопка повтора и переход к локальному району. Автоматическое переключение не меняет проект, камеру или сохранённый выбор подложки: следующий запуск снова пробует онлайн. При ручном выборе локальной карты выбор сохраняется. Информация о границах покрытия видна и при ручном выборе.

## Сборка

На Windows нужны Node.js, pnpm, Rust MSVC и Microsoft C++ Build Tools (только на машине сборки).

```sh
pnpm install --frozen-lockfile
pnpm desktop:build
```

На macOS/Linux после установки cargo-xwin, LLVM/LLD, NSIS и target `x86_64-pc-windows-msvc`:

```sh
pnpm desktop:prepare
pnpm tauri build --runner cargo-xwin --target x86_64-pc-windows-msvc
```

Результат: `src-tauri/target/x86_64-pc-windows-msvc/release/bundle/nsis/`.
NSIS включает офлайн-установщик WebView2. Пользователю не нужно устанавливать Node.js или базу данных.

`desktop:prepare` собирает отдельную копию `.fortis-desktop-stage`, не читает локальные `.env`, проверяет отсутствие приватных конфигураций в результате и SHA-256 встроенного Node.js. Каталог `.desktop-build` содержит только генерируемую поставку. Рабочий `.next` не используется.

## Проверки

```sh
node --test scripts/desktop-smoke.test.mjs
node --test scripts/offline-map.test.mjs
# При запущенной production demo на 127.0.0.1:43178:
node scripts/offline-map.browser.test.cjs
pnpm exec tsx src/shared/config/base-map-sources.test.ts
```

Smoke проверяет готовность demo, локальные моки, блокировку backend API, основные маршруты, CSP и завершение процесса при закрытии родителя. Финальная приёмка требует установки и запуска на чистой Windows x64: GIS, сценарии, 3D, повторное открытие и удаление приложения. Кросс-сборка на macOS этого не заменяет.

Установщик пока без цифровой подписи: Windows может показать предупреждение неизвестного издателя. Автообновление не добавлено.


## macOS Apple Silicon

`pnpm desktop:build:mac` на Mac с Apple Silicon подготавливает тот же demo, собирает `.app` и создаёт `.dmg` без Finder-автоматизации. В составе — официальный Node.js 22.23.4 для arm64, проверяемый по SHA-256; сервер Fortis не используется. Пакет содержит локальные карты и модели. Результат: `.desktop-build/Fortis-Demo-0.1.0-macOS-arm64.dmg`.

Образ проверен через `hdiutil verify`, его `.app` — через `codesign --verify --deep --strict`; запуск приложения, демонстрационные данные и локальная карта проверены на этом Mac. Подпись ad hoc не является Developer ID; нотариализации Apple нет, поэтому Gatekeeper может блокировать запуск после передачи. Intel Mac не поддерживается этой сборкой. Проверка на другом Mac и выпуск Developer ID/нотариализация остаются отдельными задачами.
